# Enterprise HRMS - Bugs and Fixes Log (Phases 1, 2, 3 & 4)

## Tracking Policy
Every bug identified during development, automated testing, or manual smoke testing is cataloged here with its root cause analysis (RCA), resolution, and regression test verification.

| Bug ID | Description | Severity | Root Cause | Fix Applied | Status |
|--------|-------------|----------|------------|-------------|--------|
| BUG-001 | `ModuleNotFoundError: No module named 'app'` when running pytest. | Low | Python module search path did not include current working directory by default in pytest. | Added `backend/pytest.ini` with `pythonpath = .`. | VERIFIED RESOLVED |
| BUG-002 | `ImportError: email-validator is not installed` upon Pydantic `EmailStr` field evaluation. | Medium | Pydantic v2 requires external `email-validator` package for email schema parsing. | Installed `email-validator` in backend virtual environment. | VERIFIED RESOLVED |
| BUG-003 | AnyIO thread portal hang in TestClient during pytest execution on Windows Python 3.13. | High | AnyIO `BlockingPortal` clashed with proactor loop without active main thread loop in Windows sandbox. | Configured test client fixtures with `StaticPool` and installed `httpx2` to resolve Starlette 1.10 deprecations. | VERIFIED RESOLVED |
| BUG-004 | TypeScript 5.8 `verbatimModuleSyntax` and `noUnusedLocals` compiler errors during `vite build`. | Medium | Unused icon imports and type-only imports rejected under strict tsconfig defaults. | Adjusted `tsconfig.app.json` and fixed type-only imports and union property checks. | VERIFIED RESOLVED |
| BUG-005 | `TypeError: 'code' is an invalid keyword argument for Shift` during seed data execution. | Medium | Seed dictionary passed `code` which was not declared in SQLAlchemy `Shift` table. | Aligned seed attributes with model definitions (`grace_period_mins`, `work_hours`). | VERIFIED RESOLVED |
| BUG-006 | `TypeError: 'scheduled_at' is an invalid keyword argument for InterviewSchedule`. | Low | Model field is named `scheduled_time` rather than `scheduled_at`. | Updated seed data and schema to `scheduled_time`. | VERIFIED RESOLVED |
| BUG-007 | `HTTPException 404: Employee record not found` in `verify_employee_access` on self-check-in without explicit employee ID. | High | Optional `employee_id` was passed as `None` to `verify_employee_access`, triggering 404. | Added fallback to `current_user.employee_profile.id` before calling `verify_employee_access`. | VERIFIED RESOLVED |
| BUG-008 | Pydantic 422 Unprocessable Entity on `/leave/applications/{id}/review`. | Medium | Test client passed `{"action": "APPROVE"}` instead of schema-expected `{"status": "APPROVED"}`. | Aligned test payload with `LeaveApprovalRequest` schema. | VERIFIED RESOLVED |
| BUG-009 | HTTP 404 for `GET /payroll/runs/{id}/payslips`. | Low | Sub-resource endpoint route was omitted while batch overview existed. | Added dedicated `@router.get("/runs/{run_id}/payslips")` in `payroll.py`. | VERIFIED RESOLVED |
| BUG-010 | `ModuleNotFoundError: No module named 'ml_service'` when importing `backend.ml_service`. | Medium | Absolute package import `from ml_service.service` failed when imported as top-level `backend.ml_service`. | Updated `backend/ml_service/__init__.py` to use relative import `from .service import ...`. | VERIFIED RESOLVED |
| BUG-011 | Split database file creation when commands executed from repository root. | Medium | Default `DATABASE_URL: sqlite:///./hrms.db` resolved relative to working directory rather than anchored backend path. | Anchored default SQLite path in `backend/app/config.py` to `backend/hrms.db` using `os.path.abspath`. | VERIFIED RESOLVED |
| BUG-012 | `ColumnTransformer` failure on list-of-dict input during cross-validation slicing. | High | Scikit-learn cross-validation passes sub-arrays that expect 2D array or DataFrame rather than Python list of dicts. | Implemented `to_feature_matrix` converting records to 2D NumPy array with column index slicing. | VERIFIED RESOLVED |
| BUG-013 | `NameError: name 'train_data' is not defined` in `train.py` metadata provenance assembly. | Low | Variable name was refactored to `X_train` without updating dictionary provenance references. | Aligned provenance dictionary to `len(X_train)` and `len(X_test)`. | VERIFIED RESOLVED |
| BUG-014 | AI Assistant personal leave query fallback to general policy search. | Medium | Phrase matching looked for exact substring "my leave" which failed on "What is my current leave balance?". | Expanded intent matching to check `is_my_query` and keyword sets (`leave`, `pto`, `balance`). | VERIFIED RESOLVED |
| BUG-015 | AI Assistant cross-employee privacy leak check bypassed on possessive queries ("David Miller's salary"). | High | Search looked for "salary of" rather than possessive patterns and peer employee names. | Implemented cross-employee privacy check matching private keywords alongside peer employee names. | VERIFIED RESOLVED |
| BUG-016 | TypeScript compiler errors during `vite build` (`fullName` property and `item.phase` type cast). | Medium | Inconsistent property name `fullName` vs `full_name` and strict type check on dynamic navigation item phase. | Corrected property to `user?.full_name` and safely cast `String((item as any).phase)`. | VERIFIED RESOLVED |
| BUG-017 | `TestClient` lifespan context manager hung during test fixture initialization on Windows Python 3.13. | High | `with TestClient(app):` entered Starlette `_portal_factory` AnyIO thread lock in child thread without active loop on Windows. | Replaced `with TestClient(app):` in `conftest.py` with direct `test_client = TestClient(app)`. | VERIFIED RESOLVED |
| BUG-018 | Missing self-service password recovery API endpoint and UI modal. | Medium | Password reset was only exposed for authenticated users or administrative overrides; public forgot-password was unexposed. | Implemented timing-safe enumeration-resistant `POST /api/auth/forgot-password` and recovery modal in `LoginPage.tsx`. | VERIFIED RESOLVED |
| BUG-019 | Opening website URL (`/`) immediately forced redirect to `/login` preventing public exploration. | High | Root route `/` was nested under `<ProtectedRoute>` which redirected unauthenticated visitors to `/login`. | Restructured routing in `App.tsx` nesting `/` under `PublicLayout` and reserving `ProtectedRoute` for `/dashboard` and internal portal sub-routes. | VERIFIED RESOLVED |
| BUG-020 | Missing public user registration API and contact form submission persistence. | Medium | Backend lacked dedicated public employee registration and contact inquiry persistence endpoints. | Implemented `POST /api/auth/register` (enforcing strict standard Employee role) and `POST /api/contact` with database model `ContactSubmission`. | VERIFIED RESOLVED |
| BUG-021 | Public exposure of Quick Demo Role Logins and pre-filled passwords on Login page. | High | Public login page displayed 1-click evaluation cards, demo accounts, and hardcoded default passwords, violating private SaaS requirements. | Removed quick demo login section, cleared password defaults, ensured empty initial inputs, and removed demo cards. | VERIFIED RESOLVED |
| BUG-022 | Unprotected `/api/auth/personas` and `/api/auth/switch-persona/{user_id}` endpoints. | Critical | Endpoints allowed unauthenticated callers to enumerate all user accounts and switch to Super Admin without credentials. | Secured endpoints behind strict `require_roles([RoleEnum.SUPER_ADMIN])` dependency check, blocking unauthorized access with 401/403. | VERIFIED RESOLVED |
| BUG-023 | Hardcoded default passwords in employee schema and UI provisioning modal. | Medium | `EmployeeCreate` schema and `EmployeeDirectory` modal hardcoded "Enterprise@2026" as default password. | Replaced with cryptographically secure random temporary password generation (`secrets.token_urlsafe(12)`) and removed hardcoded values from UI. | VERIFIED RESOLVED |
